# GDRFA AI-Powered Shelter Management — Full-Stack Prototype

This package contains a real separated frontend/backend prototype:

- **React + Vite frontend**: GDRFA-style operations dashboard.
- **FastAPI backend**: API, MJPEG video streams, alert updates and health data.
- **OpenCV**: reads included MP4 files frame by frame.
- **Ultralytics YOLO**: detects people in every processed frame.
- **ByteTrack**: assigns temporary anonymous track IDs across frames.
- **SQLite**: stores AI-generated alert history and officer decisions.
- **Synthetic MP4 videos and health readings**: safe demonstration substitutes for protected operational footage and sensors.

## Important first-run behavior

The Python package installation and the first YOLO launch require internet access. Ultralytics automatically downloads the small pretrained model named `yolo11n.pt` on first launch. Later launches use the cached model.

## Windows instructions

1. Install **Python 3.11 or 3.12** and select **Add Python to PATH**.
2. Install **Node.js LTS**.
3. Extract this ZIP.
4. Double-click `SETUP_WINDOWS.bat` once.
5. Double-click `START_PROJECT.bat` whenever you want to run the project.
6. Keep the backend and frontend terminal windows open.
7. Open `http://127.0.0.1:5173`.

## What is genuinely processed

The video sources are prerecorded, but OpenCV reads them continuously and YOLO analyzes the current frame while the program is running. The frontend receives an MJPEG stream generated by the backend. The boxes, confidence values, occupancy totals and track IDs are therefore produced by the backend in runtime.

## Prototype event logic

- **Dining Hall**: person counting and capacity alert.
- **Sleeping Area**: possible-fall heuristic based on a horizontal person bounding box near the floor.
- **Recreation Room**: unusual group-activity heuristic based on detected people and frame motion.
- **Restricted Corridor**: virtual-zone crossing detection.

These alerts are proof-of-concept indicators and require officer verification. A production deployment would need approved, representative training data, formal validation, security hardening, privacy controls and secured camera/sensor integrations.

## Light and dark mode
The dashboard now includes a Light/Dark button in the main header. The selection is saved in browser local storage, so the chosen theme remains active after refreshing or restarting the frontend.

## Replacing the included demonstration videos
The backend processes local MP4 files frame-by-frame. To use legally permitted real footage, replace the files in `backend/videos/` while keeping these filenames:

- `dining-hall.mp4`
- `fall-detection.mp4`
- `recreation-room.mp4`
- `corridor.mp4`

Use footage you own, footage supplied with permission, or footage whose licence explicitly permits your intended use. Do not use private shelter CCTV or identify real residents in the prototype.

## Replace demo clips with real footage

Double-click:

```text
IMPORT_REAL_FOOTAGE.bat
```

Option 1 automatically downloads two real University of Rzeszow research recordings and converts their image sequences into MP4 files. Option 2 opens curated source pages. Option 3 lets you select downloaded videos and imports them under the exact filenames expected by the backend.

See `REAL_FOOTAGE_SOURCES.md` for licensing, attribution, and presentation wording.
